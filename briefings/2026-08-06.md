## 2. 🟡 New disclosed findings / techniques

### Shai-Hulud npm Worm — 400+ Packages, Ethereum Smart-Contract C2, IDE/AI-Agent Persistence (Aug 4–5)

**Disclosed:** August 4–5, 2026 (Datadog Security Labs, Socket.dev, Snyk, SafeDep, Wiz, Aikido)  
**Affected packages / versions:** `keyv@6.0.0`, `cacheable@2.5.1`, `flat-cache@6.1.24`, `ecto@5.0.1` + 9 cacheable-family packages + 430+ others — **2,234 poisoned versions across 444 package names**  
**Reach:** keyv: 127M downloads/week · cacheable: 29M/month · flat-cache: 565M/month · file-entry-cache: 557M/month  
**Web3 relevance:** keyv is a caching layer in Hardhat, ENS indexers, and offchain oracle pipelines; flat-cache ships inside eslint, present in virtually every Hardhat/Foundry project's devDependencies

**Attack chain:**

1. **Initial compromise:** Attacker hijacked the maintainer's GitHub account and used stolen npm tokens with `bypass_2fa: true` permission to republish malicious patch-incremented versions of every package in the family.

2. **Payload delivery:** Each poisoned package ships `setup.mjs` (Stage 1, 11KB, lightly obfuscated) and `Math_Symbol.js` (Stage 2, heavily obfuscated via a 4,613-entry Base91 string table) plus a `"preinstall": "node setup.mjs"` entry in `package.json`. Anyone who ran `npm install` against an affected version triggered Stage 1 before their install completed.

3. **Credential harvesting (290+ file patterns):** SSH keys, Git credentials, npm tokens, `.env` files, AWS keys (also pulled via STS / Secrets Manager / SSM), GCP/Azure credentials, Kubernetes API tokens, HashiCorp Vault tokens, GitHub Actions runner secrets (via sudo memory read on Linux). Data exfiltrated via AES-256-GCM with RSA-OAEP wrapping.

4. **Ethereum-based C2 (critical detail):** Instead of a hardcoded domain, the payload queries **73 Ethereum RPC endpoints** calling contract `0xE1f2395ee43e45A1556EC6438a88c31B83493103` (selector `0x53ed5143`) to retrieve current C2 domains. Responses are evaluated as arbitrary JavaScript — making this a general RCE channel updatable at any time without reinfecting packages. Fallback: searches GitHub commits for marker string `thebeautifulmarchoftime` (with trailing space) and decodes signed fallback domains via an embedded RSA key.

5. **IDE and AI-agent persistence:** The worm commits `.claude/settings.json` (Claude Code SessionStart hook) and `.vscode/tasks.json` (VS Code folder-open task) to 50+ GitHub branches in the poisoned repos. Opening a cloned infected repo in VS Code or starting a Claude Code session inside it re-executes the loader silently.

6. **Self-propagating supply chain:** Once npm tokens are stolen, the malware republishes poisoned patch versions under the victim maintainer's namespace — extending the worm to entirely new package families. Additionally, attacker targets `@opensearch-project/opensearch` GitHub Actions workflows to generate valid Sigstore SLSA attestations that authenticate the malicious code.

**Remediation checklist:**
- `npm ls --depth 10 keyv cacheable flat-cache ecto 2>/dev/null | grep -E '6\.0\.0|2\.5\.1|6\.1\.24|5\.0\.1'` — run across all projects and CI images
- Check `package-lock.json` / `yarn.lock` for indirect pinning of affected versions
- Rotate **all** credentials on any machine that ran `npm install` since August 4 (npm tokens, SSH keys, AWS keys, GitHub PATs, Vault tokens, Kubernetes SA tokens)
- Audit GitHub Actions workflow runs and branch listings for unexpected `.vscode/tasks.json` or `.claude/settings.json` commits
- Search monorepos and CI containers for `setup.mjs` and `Math_Symbol.js`
- Block or alert on RPC calls to `0xE1f2395ee43e45A1556EC6438a88c31B83493103` in node/gateway logs

**CVE:** No CVE assigned as of August 6.

**Bug class:** supply-chain

### Open VSX Evil Twin Extensions — 77 Removed, 19 Sent Full CI/Repo Data (Still Installed on Developer Machines)

**Disclosed / removed:** August 3–5, 2026 (Manifold Security, The Hacker News, BleepingComputer)  
**Marketplace:** Open VSX (used by VSCodium, Gitpod, Theia, code-server — common in cloud dev containers and web3 devcontainers)  
**Period active:** July 26 – August 1, 2026

**Details:** 77 extensions impersonated legitimate tools using identical names and descriptions, published from unregistered accounts at version `0.0.1`. The real `extension.js` was replaced with data-collection code:
- **58 extensions:** sent hostname + workspace folder name to `mangorbit[.]com` (registered July 15, 2026)
- **19 extensions (high severity):** also sent full machine profile, open Git repository name/URL, and CI system metadata

The 19 high-severity variants give attackers a rich spear-phishing targeting profile for any web3 dev team running cloud dev environments. All 77 were removed from Open VSX as of August 3 — but extensions are **not auto-removed from installed environments**.

**Action:** Check your editor for unexpected extensions matching the Manifold Security IoC list; remove any version `0.0.1` of a well-known tool that you didn't deliberately install.

**Bug class:** supply-chain

### CISA KEV — CVE-2026-9198 Langflow Unauthenticated RCE (Added August 5)

**Affected:** Langflow < 1.4.0  
**Severity:** CRITICAL  
**CISA KEV added:** August 5, 2026 (actively exploited in the wild)  
**Web3 relevance:** Langflow is widely adopted in web3 for orchestrating on-chain data pipelines, oracle workflows, and LLM-based trading bots. A default deployment exposes an API that allows unauthenticated code execution — any cloud-hosted Langflow instance with access to signing keys, RPC endpoints, or private APIs is fully compromised.  
**Fix:** Upgrade to ≥ 1.4.0; enforce authentication on all API surfaces; never co-locate Langflow with signing keys unless fully isolated.

**Bug class:** access-control

## 4. 🎯 Hunt hooks

**1. Shai-Hulud blast-radius audit: your target protocol's npm org may already be poisoned.**  
The worm steals npm tokens and republishes poisoned versions under the stolen token's namespace. Any developer on a target protocol who had `keyv@6.0.0`, `cacheable@2.5.1`, `flat-cache@6.1.24`, or `ecto@5.0.1` since August 4 may have had their npm token captured — and that token may have write access to the protocol's own SDK packages (TypeScript ABIs, Hardhat plugins, custom libraries). Concrete check: search target protocol's npm org for unexpected patch bumps published after August 4 with no corresponding GitHub release or commit. A poisoned SDK package with 50,000 weekly installs is a critical-severity finding.

**2. Ethereum C2 contract as a detection signal in RPC monitoring.**  
Block and alert on calls to `0xE1f2395ee43e45A1556EC6438a88c31B83493103` in any RPC provider logs you have access to. This is a binary IoC with no false positives — legitimate DeFi protocols do not call this contract. Any call from a protocol address, relayer, multisig, or CI host in your scope signals active Shai-Hulud infection. In a bug-bounty context, confirmed infection of a protocol's deployment environment is a CRITICAL finding regardless of whether funds have moved yet.

**3. Coldcard phishing → governance key social engineering window.**  
The current wave targets retail holders with fake "migration" emails. The next, higher-value tier is protocol multisig co-signers: a single Guardian on a major lending protocol who used Coldcard hardware and is now panicked about whether their keys are compromised is a prime target for a "we'll help you verify your seed" phone scam. For any bug-bounty target: check governance documentation and forum posts for Coldcard mentions, identify which co-signers might have used affected hardware, and assess whether your protocol's multisig threshold can survive the social engineering of even one signer. File a hardware-key-hygiene advisory if the risk is present — it's an increasingly credible threat vector right now.
