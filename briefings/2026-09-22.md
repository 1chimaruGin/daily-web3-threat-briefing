# Web3 Threat Briefing — 2026-09-22

> **Scope:** Multi-chain (EVM/Solidity · Solana/Rust · Cosmos/Move · cross-chain bridges). Priority: DeFi, wallets, key infrastructure.
> **Window:** Last ~24–48h (September 21–22 UTC). **Headline: No headline-scale drain landed on Sept 21–22. Two small token-level exploits were newly disclosed (Internet Token on Base, RWC Token on BNB Chain, combined ~$374K), and the Fetch.ai/NuNet/SingularityNET bridge-key incident widened again — Bitquery now traces the same actor's unauthorized minting to a fifth token, CGV (Cogito Finance), across roughly 2.3 billion total units. Every other tracked incident — MultiversX, Blink, Nostra, DCENT, Liquid — remains open with no material resolution.**

## 1. 🔴 Active exploits (last 24h)

### Internet Token (INT) — LiquidityUnifier Exploit, ~$265K

**Chain:** Base
**Status:** CONFIRMED, first disclosed Sept 21.
**Impact:** ~$265,000.
**What happened:** Internet Token DAO's `LiquidityUnifier` contract was exploited after it trusted a caller-supplied Uniswap V3 pool address as a price/liquidity source rather than resolving the canonical INT/WETH pool itself. The attacker supplied a pool address they controlled, which the contract used to mint or value INT tokens, and extracted value from the unifier.
**Root cause:** unvalidated external input — a contract accepted an attacker-chosen pool address as a trusted price/liquidity reference instead of deriving or whitelisting the canonical pair.
**Bug class:** access-control (missing input validation) / price-manipulation (spoofed liquidity source).

**Sources:**
- [SlowMist Hacked — incident database](https://hacked.slowmist.io/) (entry: Internet Token, Base, $265,000, Sept 21 2026)

### RWC Token — Burn-Function Reserve Manipulation, ~$109.5K

**Chain:** BNB Smart Chain
**Status:** CONFIRMED, first disclosed Sept 21.
**Impact:** ~$109,460.85.
**What happened:** RWC's token contract exposed a burn function without proper access or invariant protections, letting the attacker manipulate the token's pool reserves through repeated burn calls and extract value from the resulting price distortion.
**Root cause:** missing access control / invariant checks on a burn function that can move pool reserve accounting — the same defect class seen repeatedly on BNB Chain low-cap tokens this year (ShadowFi-style burn abuse).
**Bug class:** access-control (unprotected burn function) / price-manipulation (reserve distortion).

**Sources:**
- [SlowMist Hacked — incident database](https://hacked.slowmist.io/) (entry: RWC Token, BNB Smart Chain, $109,460.85, Sept 21 2026)

No other new protocol exploit, bridge drain or key compromise was independently corroborated for the Sept 21–22 UTC window beyond these two small token-level incidents.

## 2. 🟠 Ongoing — carried forward

### Fetch.ai + NuNet + SingularityNET + CGV (AGIX/WMTx/NTX/CGV) — Stolen Bridge Signing Key (Day 4)

**Chain:** Ethereum (bridge counterpart chain is Cardano)
**Status:** CONFIRMED and now wider still. First disclosed **Sept 19** (Fetch.ai/NuNet legs); widened **Sept 20** (SingularityNET AGIX/WMTx mints confirmed as the same actor); widened again in reporting that consolidated on **Sept 21** when Bitquery's tracing added a fifth token.
**Sept 21–22 development:** Bitquery reported roughly **2.3 billion unauthorized units created across AGIX, NTX, CGV and WMTx**, all linked to the same attacker cluster. **CGV — Cogito Finance's governance token — is a newly confirmed addition** to the blast radius; prior reporting (through Sept 20) had only established FET, NTX, AGIX and WMTx. No mint-quantity or holder breakdown for CGV has been published yet, and there is no reconciled USD total for the full 2.3B-unit figure — treat it as unauthorized unit count, not confirmed value extracted. PeckShield's last full valuation snapshot (~$16.77M attacker-held: 198.3M AGIX, 649 ETH, 33.538M WMTx, plus FET/NTX proceeds) still stands as the most recent dollar figure and has not been revised upward for CGV as of this writing.

**Recap (unchanged):** root cause is a single **compromised SingularityNET bridge backend signing/authorizer key** with no rate limit or per-transaction cap on the mint/release path, which authorized value release for every token sharing that bridge's signing infrastructure. Fetch.ai's FET contracts remain confirmed unaffected directly; AGIX-to-FET conversions remain paused as a precaution.

**Root cause:** unchanged — compromised shared bridge authorizer key, asymmetric mint/release guards, no per-token or per-transaction caps. The new information is that the trusted-key blast radius now spans five token economies instead of four.

**Bug class:** key-management (compromised shared bridge signing key), access-control (no per-token or per-transaction caps on the mint/release path)

### MultiversX — VM-Level Atomicity Flaw, Mainnet Still Halted (Day 4)

**Chain:** MultiversX (EGLD)
**Status:** STILL HALTED. No public confirmation found that block production has resumed as of this writing. First disclosed **Sept 19**; cause confirmed **Sept 20**. Loss amount still **not disclosed**.
**Sept 21–22 developments:** none of substance found beyond the Sept 20 position. The team's fix is still being validated on a shadow fork before a coordinated mainnet deployment with validators, exchanges and infrastructure partners; no firm restart date has been published. A targeted recovery preserving finalized history remains under evaluation.

**Recap (unchanged):** an attacker exploited an **atomicity issue at the mainnet virtual-machine level**, causing invalid state changes to be written on-chain; the team paused the network to contain it. Public API, xPortal, Explorer, Wallet, Bridge, xExchange and xLaunchpad remain degraded. Users are still told not to submit or rebroadcast transactions and not to deposit or withdraw EGLD or ESDT via exchanges or bridges. Bithumb, Kraken and Upbit all still have EGLD deposits/withdrawals restricted.

**Root cause:** still not publicly detailed beyond "VM-level atomicity" — treat as an unpatched client/VM implementation bug until MultiversX publishes its promised technical report.

**Bug class:** logic-error / client-implementation (non-atomic state transition at the VM layer)

### Liquid Network / Blockstream — Elements Range-Proof Cache Bug (Day 16)

**Chain:** Liquid (Bitcoin sidechain)
**Status:** PARTIAL RECOVERY (Day 16, counted from the Sept 7 public disclosure). Block production and LBTC transfers have been running normally since **Sept 10**; peg-in via SideSwap reopened **Sept 11**. **Peg-out (BTC redemption) remains paused**, pending confirmation of a full 1:1 peg, a network upgrade, testing, and an independent security review.

## 4. 🎯 What to hunt

**1. Any function that accepts a pool/pair address as a parameter instead of deriving it**

Today's Internet Token exploit is the textbook version of this: `LiquidityUnifier` trusted a caller-supplied Uniswap V3 pool address as its price/liquidity source. If a contract in scope takes a pool, pair, or oracle address as an argument — from a user, a router call, or an external integrator — check whether it validates that address against the canonical factory-derived pair (`factory.getPool(tokenA, tokenB, fee)` or equivalent) before trusting its price or reserves. If it doesn't, an attacker can point it at a pool they control and manipulate the trusted reference.

**2. Burn functions without matching access/invariant checks**

RWC's exploit is a repeat of a well-worn BNB Chain pattern: a `burn` function that anyone can call, with no check tying the burn to a legitimate LP or reserve-adjustment path, lets an attacker move reserves and mint value elsewhere out of sync. For any token with a public or lightly-gated burn function, check whether reserve accounting anywhere in the protocol assumes burns only happen through a trusted path — if so, that assumption is a finding.

**3. Shared-key blast-radius mapping — now proven to span five token economies, not four**

Unchanged guidance, reinforced again today: before scoping a bridge/converter audit down to a single contract, enumerate every other contract, token and chain that trusts the same authorizer key or multisig. The Fetch.ai/SingularityNET incident has now widened three times (Sept 19 → 20 → 21) as tracing firms found more tokens sharing the same compromised key. Assume any "one converter, one key" scoping is incomplete until you've mapped the full set independently.

**4. VM/client-layer atomicity and collateral-cap checks — still open, still unresolved**

MultiversX's mainnet has now been halted for four days on an unpublished VM-level atomicity bug, and Nostra's market has been paused for six days on a market-cap-relative borrow cap gap. Both remain live, unresolved reference cases — if scope includes execution-client code or lending-market collateral listings, these bug classes are still paying out in production.
