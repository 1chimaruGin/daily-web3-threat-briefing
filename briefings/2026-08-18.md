## 1. 🔴 Active exploits (last 24h)

### Harmony ONE — Chain Rollback Announced (Aug 17) — Scale Revised to 3.01 TRILLION ONE

**Chain:** Harmony ONE (PoS, cross-shard)
**Status:** ESCALATING — Rollback plan officially announced Aug 17. This is the single biggest development in the last 24h.

**Revised scale (NEW):** Revised from initial "4 billion ONE" to **3.01 trillion ONE** forged across six transactions into four exploiter wallets. The attacker exploited a cross-shard receipt validation flaw (full technical root cause in yesterday's Aug 17 briefing) that counted public keys in a signature mask without verifying those keys had signed anything.

**Rollback plan (NEW Aug 17):**
- **Target checkpoint:** Shard 0 block 92,730,034 · Shard 1 block 94,978,278 — both at 23:25:37 UTC Aug 11 (before the exploit)
- **Transactions discarded:** 109,000+ regular user transactions (the six exploit txs plus all subsequent legitimate activity on the affected shards)
- **Approach:** Complete database replacement rather than standard rewind, because Harmony's in-place revert function does not fully clear cross-shard receipts, indexes, and snapshots — leaving residue that could preserve the attack surface or cause validator state divergence
- **Validator action required:** All validators must pull the replacement databases and restart consensus from the reviewed checkpoint
- **Bridge.harmony.one:** Still suspended; no reactivation timeline given

**What this means for hunters/traders:**
- Any on-chain state written after block 92,730,034 (shard 0) / 94,978,278 (shard 1) will be **erased** — including legitimate DeFi positions, NFT transfers, staking claims, and governance votes
- Exchanges holding frozen attacker ONE may still face liability depending on rollback finality timing
- 97% of forged tokens reportedly reached exchange deposit addresses before the bridge was halted; exchange losses remain TBD pending rollback confirmation
- Token price: -37% to ~$0.00077; not further moved on rollback announcement (market had anticipated it)

**Bug class:** logic-error (consensus / signature validation)

### Coldcard Bitcoin Entropy Exploit — Day 19: Still No Compensation Framework

**Chain:** Bitcoin
**Status:** ONGOING — No new confirmed sweep wave in the Aug 17–18 window. No victim-compensation framework published by Coinkite as of Aug 18 UTC. On-chain migration of BTC from legacy cold storage continues (~210K BTC moved to new seeds since initial disclosure).
**Cumulative losses:** ~$116–130M+ (5,200+ addresses across multiple waves since Aug 4)

**Root cause (unchanged):** Coldcard firmware v4.0.1 (March 2021) substituted a weak software PRNG for the hardware TRNG during seed generation, collapsing effective entropy from 128 bits to ~40 bits — brute-forceable offline without physical device access.

| Device | Affected firmware | Required action |
|---|---|---|
| Coldcard Mk3 | v4.0.0 – v5.0.3 | **Move ALL funds immediately — no firmware fix possible** |
| Coldcard Mk4 / Mk5 | < v5.6.0 | Upgrade ≥ v5.6.0, fresh seed, migrate funds |
| Coldcard Q series | < v1.5.0Q | Upgrade ≥ v1.5.0Q, fresh seed, migrate funds |

> Seeds generated with dice-roll entropy bypass are **not** affected. Any seed generated on Mk3 or pre-upgrade Mk4/Mk5/Q must be treated as fully compromised.

## 2. 🟡 New disclosed findings / techniques

### Adform CDN Supply-Chain Attack — Clipboard Wallet-Address Swapping (Ongoing Active Reporting)

**Discovered:** July 27, 2026 · **Active reporting Aug 17–18**
**Chains affected:** Bitcoin, Ethereum, TRON (address formats targeted)
**Scale:** ~1,800 downstream customer websites carried the malicious code

**What happened:** Attackers compromised the advertising technology firm Adform and modified its widely-deployed CDN JavaScript file `trackpoint-async.js`. The poisoned script monitors the user's clipboard for cryptocurrency wallet addresses (BTC, ETH, TRON formats) and silently replaces any detected address with an attacker-controlled address — a "clipboard clipper" attack delivered via a legitimate-looking analytics script embedded in thousands of sites.

**Attack properties:**
- No user-facing indicator; the swap happens in the browser clipboard silently when a crypto address is copied
- Operates only while the affected page is open (no persistence, no binary install)
- Distribution via Adform's CDN meant **zero direct breach required** for 1,800 sites — any site loading the Adform tracking script was affected
- ChangeNOW froze some proceeds; Adform remediated the script on July 27 and notified affected clients
- Losses: unquantified (clipboard hijacking is passive; losses depend on victim copy-paste behavior)

**Why this matters to bug hunters:** DeFi frontends routinely embed third-party analytics, CDN-hosted JS, and ad-tech scripts. A poisoned CDN payload can swap deposit addresses, withdraw-to addresses, or override Web3 wallet prompts for ANY user visiting those sites. This class of attack is technically trivial but operationally devastating and often below the audit scope of smart contract reviews.

**What to check in your targets:**
1. Enumerate all third-party CDN scripts loaded by the protocol's frontend (`Content-Security-Policy` header; view source)
2. Identify any clipboard-reading or address-displaying JS that could be intercepted or replaced
3. Check for lack of subresource integrity (`integrity="sha384-..."`) on CDN-loaded scripts — without SRI, any CDN compromise swaps the payload silently
4. Verify the protocol's frontend does not allow dynamic script injection via URL parameters or user-controlled content

### Chain Rollback as Incident Response — Systemic Risks (New Research Angle from Harmony)

**Chains at risk:** Any PoS or dPoS chain with a reorg / rollback capability, particularly those with cross-shard or cross-chain state

**Pattern:** The Harmony rollback introduces a class of **secondary systemic risk** that is rarely modeled in DeFi protocol threat models: what happens to protocols built on a chain that undergoes a rollback?

Key risks that surface when a L1 rolls back:
- **Replay exposure:** Transactions that were valid before the rollback target block can be re-broadcast after the rollback; bridges, DEXs, and lending protocols that lack nonce or replay protection on their own cross-chain messages may accept duplicate submissions
- **State divergence in dependent L2/bridges:** Any bridge or L2 that anchored to a Harmony state commitment after block 92,730,034 holds an anchored root that now doesn't correspond to canonical chain state — operators must verify their source-of-truth still matches
- **Governance and snapshot invalidation:** Governance votes, snapshot checkpoints, and airdrops recorded after the rollback target are erased — protocols using snapshot.org or on-chain checkpoints for token distribution need to identify if any valid user actions are now orphaned

## 4. 🎯 Hunt hooks

**1. Audit bitmask / key-list quorum logic for signature-count vs. signature-verification confusion.**
The Harmony exploit — now confirmed at 3.01T ONE scale — is the canonical 2026 example: code counted keys present in a signature mask without verifying any of those keys actually signed the message. This is exploitable with zero valid signatures. Target: IBC light clients, LayerZero DVN contracts, Axelar CGP verification, any custom multisig using packed `bytes` to encode signer sets. The check you're looking for: does the quorum threshold comparison happen *before* or *after* iterating over actual `ecrecover`/`ed25519_verify` calls? If before, it's likely exploitable.

**2. Enumerate CDN-loaded JS on DeFi frontends and verify Subresource Integrity.**
The Adform attack shows that clipboard-swapping can be deployed to 1,800 sites with a single CDN compromise. In your targets: load the protocol's frontend, open DevTools → Network, filter for JS loaded from external domains. Check each for an `integrity="sha384-..."` attribute (`<script integrity=... crossorigin="anonymous">`). Missing SRI on any third-party script that runs on pages where users copy wallet addresses or confirm transactions is a valid frontend vulnerability worth reporting. This is especially acute on deposit/withdraw/bridge pages.

**3. Assess rollback recovery exposure for any protocol deployed on Harmony ONE.**
If you audit or hunt on protocols deployed on Harmony: verify which block their latest deployment, proxy upgrade, or governance vote was captured at. If it's after block 92,730,034 (shard 0), that on-chain state is being erased. Check whether the protocol has a replay-protection mechanism on its cross-chain messages, and whether its bridge anchors / snapshot roots are invalidated by the rollback. File a report if the protocol has no documented rollback-recovery procedure and holds user funds.
