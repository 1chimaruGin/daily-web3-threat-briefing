### TENDRIL/USDT Pool — Sell-Hook/Burn-Sync Reserve Manipulation Drains PancakeSwap V2 Pool (~$555,000, BNB Smart Chain)

**Chain:** BNB Smart Chain (BSC).
**Status:** Confirmed loss; no attacker identity disclosed; no fund-recovery or negotiation effort reported.
**Impact:** CertiK and security researchers ExVul/ScaleBit put the pool's net loss at approximately **$555,000** (separately described as ~$550,000 "drained in total" by other research). An early alert from monitoring service TenArmorAlert had initially pegged losses lower, at approximately **$309,000** — cryptobriefing.com's reporting explicitly attributes the gap to differing measurement methodologies (a pool's total drained balance, the attacker's take after costs, and victims' net loss can all produce different totals from the same transactions), not to a factual dispute.
**What happened:** On Nov 4-5, 2026 (on-chain activity dated Nov 4; coverage published Nov 5), an attacker exploited a flaw in the TENDRIL token's custom "sell hook" logic on its PancakeSwap V2 TENDRIL/USDT pair. Security researchers traced the attack to function calls including `PoolControl.sellToken` paired with a controlled burn operation: the attacker used the burn to manipulate the pool's recorded token reserves *before* an external transfer had finished executing, letting the contract use stale, manipulated numbers to price the pool mid-transaction. Because PancakeSwap (like other AMMs) prices assets off the ratio of tokens sitting in a pool, artificially shrinking one side made the other side look cheap to withdraw, and the attacker used that gap to pull out nearly the entire USDT balance. There was no compromised admin key and no bug in PancakeSwap itself — the flaw was entirely in TENDRIL's own custom token contract.
**Root cause:** A checks-effects-interactions / state-update-ordering failure — the sell-hook and burn/sync functions altered pool-balance state mid-transfer, before reserves settled, rather than only after transfers completed.
**Remediation:** None reported beyond the general security-researcher recommendation that sell hooks and burn functions touching pool balances need strict ordering (state changes only after transfers complete). No team statement or post-mortem found.
**Attribution:** None.
**Bug class:** logic-error / AMM reserve-manipulation via a custom token's sell-hook and burn/sync functions executing mid-transfer — an ordering flaw, not classic reentrancy, since no external call reentered the vulnerable function; the vulnerable state read simply occurred before the vulnerable state write had resolved.

### Loopscale — Solana Lending Protocol Pauses After Week-Long Volumetric API Attack (No Confirmed Fund Loss)

**Chain:** Solana.
**Status:** Active; protocol self-paused Nov 5, 2026, pending completion of a security review. No user funds lost.
**Impact:** **$0 confirmed user loss.** Loopscale stated affected vaults have already been "made whole" and reiterated "all deposited user funds are secured." The exact amount the protocol had to replenish, and the attacker's take if any, was not disclosed.
**What happened:** Over the week prior to Nov 5, Loopscale's API received more than **30,000 malicious requests per day** targeting its SOL and USDC "Genesis" vaults — an older vault design. Loopscale described this explicitly as a volumetric, API-layer campaign by "a sophisticated actor," distinct from a smart-contract pricing exploit: no vulnerability in vault pricing logic or contract code was cited as the vector. The team identified four addresses (two Solana-format, two Ethereum-compatible-format) tied to the suspicious activity and paused all protocol activity to limit impact while it completes a security review; the UI and loan-repayment functionality are slated to be restored first (to prevent borrowers facing unexpected liquidations), with full resumption conditional on the review's completion. Loopscale says it is working with federal law enforcement and outside security professionals.
**Root cause:** Not a smart-contract bug — a sustained, high-volume abuse of the protocol's public API against vault endpoints. Exact exploitation technique (credential stuffing, rate-limit evasion, endpoint enumeration, etc.) not disclosed.
**Remediation:** Protocol-wide pause; affected vaults already replenished; security review in progress before resumption.
**Attribution:** None disclosed.
**Bug class:** availability / volumetric API-layer abuse against vault-management endpoints — a reminder that "no funds lost" incidents against DeFi infrastructure are still worth tracking, since the attacker's actual goal (probe for a pricing/liquidation edge case, exhaust rate limits, or something else) was not established in available reporting.

### Chainalysis Breach — Escalation Confirmed: Password Hashes and Live Tokens Exposed for All Users (Day 8)

**Chain:** Not a blockchain incident — a breach of crypto-forensics vendor infrastructure widely relied upon across the industry, including by law enforcement and national-security customers; included here given its direct relevance to key/credential infrastructure in the Web3 security ecosystem.
**Status:** Active disclosure; significantly escalated from the initial Oct 30 characterization. Several Chainalysis products partially offline.
**Impact:** Not a funds-loss incident. Chainalysis's Nov 4 ("Wednesday night") update states: **"certain customer information including names, usernames, password hashes and live tokens for all Chainalysis users were exposed to a malicious actor."** This is a material escalation from the company's initial Oct 30 disclosure, which said only names, emails, user IDs and role labels were exposed and that there was "no evidence" that authentication credentials or session tokens had been accessed.
**What happened:** Chainalysis detected an external actor using what it calls "offensive agentic techniques" to gain unauthorized access to its systems and internal tools on Oct 30. The company has still not explained what "offensive agentic techniques" or "live tokens" mean, nor how the exposed passwords were hashed. In the Nov 4 update, Chainalysis disclosed that some KYT (Know Your Transaction) customer accounts "appeared to have been accessed," and separately disclosed a distinct "on-path attack" that exposed some customers' passwords via interception — described as contained, with affected accounts locked. As a precaution, Reactor and Data Solutions were taken offline Monday (Nov 2); the KYT UI/API, other address-screening products, and the company's own login page were subsequently also taken offline after "abnormal activity." Restoration of KYT/Address Screening was planned for "Thursday" (Nov 5) pending customers submitting trusted IPs for an allowlist; no restoration date was given for Reactor, Data Solutions, or Chain (Beta) as of the fetch. Chainalysis states it continues to have "no evidence that any investigations data has been accessed or Chainalysis attribution data has been manipulated," and has not said whether every category of exposed data applies to every one of its 1,500+ customers, nor how many users were affected in total.
**Root cause:** Unknown/undisclosed — the "offensive agentic techniques" intrusion method has not been technically detailed in any public statement.
**Remediation:** All users required to reset passwords and rotate API keys; customers urged to navigate directly to the login page rather than follow links in password-reset emails; third-party cybersecurity experts engaged to investigate.
**Attribution:** None disclosed.
**Bug class:** credential-and-session-management failure at a widely-relied-upon crypto-forensics vendor — now confirmed to include password hashes and live authentication tokens, not just low-sensitivity metadata, for its entire customer base.

### Binance — Attacker Cluster Uses Aave as Cash-Out Venue; Laundering Flows Into Chinese Networks via TRON; Anti-Laundering Alliance Revealed Disbanded (Day 8)

**Chain:** Ethereum (Aave borrow), Solana/TRON/Bitcoin (laundering routes); recovery figures otherwise unchanged.
**Status:** Recovery essentially complete per Binance's own figures (unchanged: ~98% replenished, ~$2.85B frozen); laundering and on-chain cash-out activity continues.

Aave's broader precautionary freeze has been lifted for most markets, though USDT/USDC/USDT0/POL/WAVAX/sAVAX/XAUT/PAXG/OP remain at zero loan-to-value and cannot be used as new collateral.
**Attribution:** Unchanged — FBI/TRM Labs/Chainalysis maintain North Korea/TraderTraitor attribution.
**Bug class:** Unchanged (key-management / EIP-7702 delegation persistence mechanism); this window adds a DeFi-cash-out angle (overcollateralized borrowing against freeze-exempt collateral as a way to extract spendable ETH from frozen stablecoin holdings) and a laundering-infrastructure angle (loss of a dedicated TRON-focused anti-laundering alliance at the exact moment its coverage area is being used at scale).

### Mercado Bitcoin — Exchange's Own Estimate Falls to $36.3M as Independent Trace Rises to $48.6M; Draining Continued Hours Past "Contained" Claim (Day 5)

Phased reopening (view-only) still scheduled for Nov 9; no date given for trading/withdrawal restoration.
**Attribution:** None established. Link to BitMart remains alleged, not confirmed by either exchange.
**Bug class:** Unchanged (key-management / transaction-authorization-signing-credential compromise), materially reinforced by evidence of persistent signing access past the exchange's containment claim.

## 4. 🎯 What to hunt

**1. Sell-hook / burn-sync state-ordering bugs in custom AMM-pair tokens (TENDRIL, this window)**

TENDRIL is a reminder that "no reentrancy, no admin-key compromise" doesn't mean "no state-ordering bug." Any custom token with a sell tax, burn-on-sell, or auto-liquidity mechanism that touches pool reserves needs its hook functions audited specifically for *when* they write to state relative to when transfers actually complete — a burn or sync call that fires before an external transfer settles can let an attacker manipulate the price the pool itself believes is current, mid-transaction, without ever reentering a function. For bounty/audit work: grep any custom DEX-pair token for sell hooks, tax-processing logic, and burn/sync calls, and trace the exact ordering of balance writes against the surrounding transfer.

**2. API-layer/volumetric abuse against DeFi vault endpoints as its own attack surface (Loopscale, this window)**

Loopscale's incident had no smart-contract bug at all — just a sustained, high-volume attack against its API targeting specific (older) vaults. This is a reminder that "the contracts are safe" doesn't mean "the system is safe": rate-limiting, request authentication, and anomaly detection on protocol-facing APIs and indexers are in-scope attack surface for any protocol whose UI or backend mediates vault interactions, even when the on-chain logic itself is unexploitable. If you're auditing a lending/vault protocol this week, ask what happens to vault state or backend assumptions under sustained API abuse, not just under a crafted transaction.

**3. Credential/session exposure at third-party infrastructure vendors as a supply-chain risk for crypto-adjacent orgs (Chainalysis, this window)**

The Chainalysis escalation — from "names and emails only" to "password hashes and live tokens for all users" — is a sharp reminder that initial breach disclosures from any vendor should be treated as a lower bound, not a final answer, especially when the vendor hasn't explained its own intrusion method ("offensive agentic techniques" remains undefined). For any protocol, exchange, or custody provider that integrates Chainalysis (or similar analytics/compliance vendors) via API keys or SSO, now is the moment to rotate those credentials rather than wait for a vendor's "all clear."

**4. Overcollateralized DeFi borrowing as a cash-out channel for frozen stablecoin holdings (Binance/Aave, this window)**

The Binance attacker cluster's $44.6M Aave WETH borrow illustrates a laundering pattern worth knowing for any protocol holding large freeze-exempt lending markets: an attacker sitting on frozen/freezable stablecoins can still extract spendable, harder-to-freeze assets (WETH, in this case) by posting the frozen asset as overcollateralized debt and walking away from the position. This isn't a contract bug — Aave's accounting worked exactly as designed — but risk teams at any lending protocol with large stablecoin markets should model this exposure explicitly, and per-account borrow caps (as LlamaRisk is proposing) need to account for Sybil/wallet-splitting evasion, as Synthetix's Kain Warwick flagged in pushback on the proposal.

**5. Don't trust a victim's own "contained" timestamp without on-chain verification (Mercado Bitcoin, this window)**

Bitquery's finding that Mercado Bitcoin's wallets kept draining for four hours after the exchange's public containment claim is a reminder for incident responders and bounty triagers alike: a victim's self-reported containment time is a claim, not a fact, until checked against on-chain activity. If you're doing any kind of post-incident forensic work this week, independently verify the stated containment window against the actual transaction timeline before accepting it.
