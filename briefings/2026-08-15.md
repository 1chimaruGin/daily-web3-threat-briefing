### Coldcard Bitcoin Entropy Exploit — Day 16: Panic Migration Wave Still Rolling

**Chain:** Bitcoin
**Status:** ACTIVE — no confirmed Wave 5 drain in the Aug 13–15 window, but ~210,000 BTC has migrated out of long-term cold-storage as users re-evaluate legacy Coldcard seeds. FBI / DOJ crypto asset recovery unit confirmed involvement Aug 5. Coinkite compensation framework details still pending.
**Cumulative losses:** ~$116–130M (5,200+ addresses; four documented attack waves since Aug 4)

**Root cause (unchanged):** A build-configuration error in Coldcard firmware v4.0.1 (March 2021 release) silently replaced the hardware TRNG with a weak software PRNG fallback during seed generation. Effective private-key entropy dropped from 128 bits to ~40 bits — brute-forceable offline without physical wallet access. At least 15 separate attacker groups are now exploiting the disclosed technique.

**Remediation matrix (unchanged — if you haven't acted, act now):**

| Device | Affected firmware | Required action |
|---|---|---|
| Coldcard Mk3 | v4.0.0 – v5.0.3 | **Move ALL funds immediately** — no firmware fix possible |
| Coldcard Mk4 / Mk5 | < v5.6.0 | Upgrade to ≥ v5.6.0, generate fresh seed, migrate funds |
| Coldcard Q series | < v1.5.0Q | Upgrade to ≥ v1.5.0Q, generate fresh seed, migrate funds |

> Seeds generated via dice-roll entropy are **not** affected. Any seed created on Mk3 or pre-upgrade Mk4/Mk5/Q while the affected firmware was active must be treated as compromised.

**Bug class:** key-management

### BTCPay Server LND Macaroon Auth-Bypass — Day 8

**Chain:** Lightning Network (Bitcoin)
**Status:** Patch v2.4.2 available since Aug 8. Critical residual: LND admin `.macaroon` credentials **never expire** — any node accessed before patching carries a live full-admin credential that updating BTCPay alone doesn't revoke.

**If you run BTCPay Server and haven't completed remediation:**
1. Confirm BTCPay ≥ v2.4.2
2. Stop BTCPay + LND → delete `~/.lnd/data/chain/bitcoin/mainnet/{admin,invoice,readonly}.macaroon` → restart LND → restart BTCPay (LND regenerates fresh macaroons on startup)
3. Audit LND logs for unexpected `SendPayment`, `CloseChannel`, or `ConnectPeer` calls since Aug 1

**Bug class:** access-control, key-management

### WhiteCobra "Solidity Pro" VS Code Campaign — Day 5: Full-Blown Credential Stealer Targeting Web3 Devs

**Chain/Platform:** Developer tooling (VS Code Marketplace, Open VSX), multi-platform
**Disclosed:** August 10–11, 2026
**Attribution:** WhiteCobra threat actor group (public reporting; "Operation Solidity Pro")

**What it does:** Two malicious publishers — `helper-beeps` and `web3devtoolsx` — distributed the `solidity-pro` VS Code extension with Solidity-themed branding. Early versions (1.0.0 – v2.4.x) beaconed to Cloudflare Workers to fetch an encrypted Python payload and execute it. The current generation (v3.0.0+) is a full-blown information stealer that collects:

- Browser extension wallet seeds (MetaMask, Phantom, etc.)
- Crypto wallet files and private key stores
- API keys, SSH keys, source-control tokens (GitHub PATs)
- Telegram bot tokens
- All captured data exfiltrated via Telegram bot upload

The attacker technique "drops a detached Python payload **outside the extension host**" — the payload escapes the VS Code sandbox and runs with the developer's local OS privileges. Download counts were artificially inflated and the extensions were promoted via social media to build apparent legitimacy.

**Current status:** Neither `helper-beeps/solidity-pro` nor `web3devtoolsx/solidity-pro` is available on Open VSX, but the GitHub repository (`web3devtoolsx/solidity-pro`) remains publicly accessible. Variants may reappear under new publisher names.

**Who is at risk:** Any Web3 / Solidity developer who installed `solidity-pro` from VS Code Marketplace or Open VSX. If you have the extension installed: **remove it immediately**, rotate all secrets accessible from that machine (wallet seeds, private keys, API keys, SSH keys), and treat the machine as compromised.

**The broader pattern:** Malicious VS Code extensions are now a primary developer-targeted supply chain vector. Extension vetting is weak — download counts and social proof can be faked. The Solidity/Web3 developer niche is a high-value target (direct private key access).

**Bug class:** supply-chain, key-management

### Governance Attack Anatomy — BonkDAO Post-Mortem (July 7, Technique Spotlight)

**Chain:** Solana
**Amount:** $20M in BONK treasury tokens drained
**Root cause:** No contract exploit — the DAO governance system worked exactly as designed. The attacker spent ~$4.4M to buy just over 1% of BONK's circulating supply over several days, accumulated a dominant voting share, submitted a malicious proposal, and passed it with 99.9% "yes" votes. Only 7 addresses voted; the attacker was effectively the sole voter. No timelock, no quorum floor calibrated to treasury value, no multisig veto on treasury withdrawals.

**Why it's in today's briefing:** This is the canonical **treasury governance attack** template for 2026. The pattern generalizes to any DAO with:
1. Token-based voting with no minimum participation requirement
2. Treasury withdrawal proposals requiring only a simple governance vote
3. No time delay (timelock) between proposal passage and execution
4. No multisig backstop on treasury contracts

Small-cap DAO treasuries on Solana, Ethereum, and Cosmos are sitting targets. The attack is cheap relative to treasury size — $4.4M spent to drain $20M (4.5x leverage on the attack).

**Bug class:** logic-error (governance design)
**Sources:**
- [CoinDesk — BONK DAO $20M treasury drain via malicious proposal](https://www.coindesk.com/markets/2026/07/07/bonk-faces-usd20-million-treasury-drain-after-attacker-spends-usd4-million-to-pass-malicious-proposal)

### CVE-2026-48054 — OpenZeppelin Contracts Wizard Code Injection (Day 65 — Still Unpatched in Many CI Pipelines)

**Affected:** `@openzeppelin/wizard` npm ≤ 0.10.8
**Severity:** HIGH (CVSS 8.8) | **Advisory:** GHSA-4x76-22x2-rx8v

Unsanitized `opts.name` / `opts.uri` user inputs are interpolated into generated Hardhat (`test/test.ts`) and Foundry (`test/<Name>.t.sol`) test scaffolds without escaping. A crafted input breaks out of its string literal context and executes arbitrary code when a developer runs `npm test` or `forge test`. CI/CD pipelines that auto-generate and immediately test Wizard output are especially exposed — an attacker can share a crafted Wizard URL and the exploit triggers on download + test.

**Fix:** `npm install @openzeppelin/wizard@^0.10.9`
**Hosted wizard.openzeppelin.com is already patched** — local/CI installs that haven't updated remain vulnerable.

## 4. 🎯 Hunt hooks

**1. Audit your VS Code extensions RIGHT NOW — and your team's.**
The Solidity Pro campaign shows attackers are fluent in the developer trust vector. Check every team member's VS Code installation for extensions from unfamiliar publishers using Solidity, Web3, or blockchain branding. On Mac/Linux: `ls ~/.vscode/extensions/ | grep -i solidity`. Check publisher names on VSCode Marketplace — if a publisher has few other extensions, low history, and crypto-themed branding, treat it as high-risk. Also check `.vscode/extensions.json` in your project repos — an attacker can add a recommended malicious extension to CI environments via this file. For your own tools: audit all npm packages in `package.json` that touch your dev environment for postinstall scripts (`npm explain <pkg>` or `npm pack` and inspect).

**2. Hunt governance attack surfaces: low quorum + no timelock + treasury-direct.**
For any DAO protocol in your scope: (a) Can a single whale wallet (>1% circulating supply) unilaterally pass a governance proposal? (b) Is there a timelock between proposal execution and treasury transfer? Even a 24h timelock would have given BonkDAO time to intervene. (c) Does the treasury contract require additional multisig approval or just the governance vote? The attack template is: accumulate voting tokens quietly → submit benign-looking proposal → execute treasury drain. Check Snapshot/Tally configurations and onchain Governor contracts for `votingDelay`, `votingPeriod`, and `timelockDelay` values. A `timelockDelay` of 0 or very low (e.g., 1 block) combined with low `quorumNumerator` is a critical finding.

**3. Map your infrastructure credentials like an attacker would.**
The Coldcard, BTCPay LND, and ChainDrop incidents all share a common thread: credentials stored in predictable, readable locations on developer machines that also run Web3 tooling. Checklist: (a) LND macaroons in `~/.lnd/`? Rotate them. (b) Mnemonic seeds or private-key files in dotfiles, `.env`, or `~/Downloads`? Move them to hardware or air-gapped storage. (c) AWS/GCP credentials co-located with blockchain RPC nodes? Segment them. If a Solidity Pro-style extension, ChainDrop-infected npm package, or afd.sys LPE gains foothold, lateral movement to wallet keys on the same machine is near-instant. The attack surface reduction here is architecture, not patch management.
