### Railway Hosting-Provider Breach Linked to ~$371,000 in Crypto Theft (Day 2)

**Chain:** At least 19 EVM-compatible chains (victim wallets); hosting-platform compromise is chain-agnostic.
**Status:** New. Railway — a cloud application-hosting platform used by more than 2 million developers, including crypto-adjacent services and individual builders — disclosed a security incident at roughly 21:51 UTC on Oct 21, 2026: an unauthorized third party gained access to systems storing customer environment variables and, for some of them, obtained the decrypted contents (which can include API keys, database passwords, and private registry credentials). Blockchain security researcher Taylor Monahan linked the breach to roughly **$371,000** in cryptocurrency theft, tracing more than 500 transactions across over 200 distinct addresses on at least 19 EVM networks, with the first known theft transaction at 19:36 UTC Oct 21 — more than two hours **before** Railway's own public disclosure. Railway has not independently confirmed the $371K figure or the precise mechanism by which the attacker obtained wallet-signing credentials; the company said its initial investigation suggests impact "may be limited to a subset of users," paused deployments, reset storage-bucket credentials and GitHub tokens for customer accounts, and urged all customers to rotate environment variables, API keys, and registry credentials. Railway also said it believes the incident "may be connected to a series of attacks against platform companies that were intended to compromise AI inference providers," without naming the attackers or targeted providers.
**What happened / root cause:** Compromise of a third-party hosting provider's secrets-storage layer; per Monahan, the attacker used what she described as "a relatively standard wallet sweeper script" against private keys that had been stored as plaintext-reachable environment variables by developers/services hosted on Railway — i.e., the loss traces to how and where private keys were stored in deployment infrastructure, not to a smart-contract bug.
**Bug class:** key-management / infrastructure-secrets-exposure — a hosting-provider-level supply-chain compromise that reached private keys stored outside any wallet's own security model.

## 3. 🟢 Advisories & patches

### EIP-7702 Delegation Drainers — Persistent Pattern, Not Newly Dated to This Window

Not a new event this window, but worth flagging as a live pattern for wallet/UX security work: EIP-7702 ("Pectra") delegation authorizations, once signed, can sit dormant for days or weeks before an attacker activates them via a sponsored (gas-free, so the victim never sees a pending transaction) transaction that drains the account in one atomic move. Research from trading firm Wintermute found more than 97% of malicious EIP-7702 delegations observed on Ethereum point to copies of a single reusable sweeper contract nicknamed "CrimeEnjoyor," which automatically sweeps any ETH, NFTs, or tokens that land at a delegated address with no further signature required. Individually reported cases include a ~$1.54M loss flagged by Scam Sniffer (Oct 10, 2026) and a ~$22,770 loss tied to a sponsored-transaction drain (Oct 14, 2026) — both outside this window's 24-48h cutoff, so not treated as new incidents here, but the underlying mechanism remains active. Mitigations cited: check wallet delegation state before signing anything described as a "batch," "authorization," or "delegation" action; treat gasless/sponsored-transaction offers as a red flag; keep high-value holdings in a wallet that has never signed an EIP-7702 authorization; and if an authorization is suspected to be compromised, move funds to a new address rather than relying on revocation alone. The ERC-7730 "clear-signing" standard is cited as an industry mitigation effort still unevenly adopted.
**Bug class:** signature-hygiene / delegation-authorization-abuse.

## 4. 🎯 What to hunt

**1. Cross-chain payment-before-release atomicity (WAX pattern, new this window)**

WAX's bridge let a withdrawal be released on two chains (Solana, Ethereum) without confirmed payment on the third (WAX itself). For any bridge audit: enumerate every leg of a multi-chain withdraw/release flow and verify there is a single, atomic, independently-checked gate — not three chains each trusting that "the others already checked" — before value moves on any side.

**2. Hosting/dev-infrastructure as a path to private keys (Railway pattern, new this window)**

Railway's breach is a reminder that key-management failures increasingly happen one layer removed from the wallet or the chain: a compromised hosting provider's secrets store can expose private keys that developers stored as "just an environment variable." For wallet, bot, or treasury-ops security reviews, map every place a signing key is stored outside a dedicated KMS/HSM — CI/CD secrets, PaaS environment variables, container registries — and ask what happens if that single store is breached.

**3. Address-retirement hygiene after a prior breach (CoinDCX dispute, new this window)**

Whether or not CoinDCX's explanation holds up, the dispute itself is the lesson: an address compromised in a past breach that keeps receiving gas or sweeping funds into current infrastructure months later is a liability regardless of attacker intent. For exchange/custodian security work, verify that addresses flagged in a past incident are actually isolated from current hot-wallet flows, not just reclassified as "legacy."

**4. EIP-7702 delegation/signature hygiene (standing pattern, reinforced)**

The CrimeEnjoyor sweeper-contract concentration (97%+ of malicious delegations) means this is now a commodity attack, not a novel technique. Any wallet or dApp that uses batch/delegation signing flows should be checked for how clearly it surfaces a delegation-authorization request versus a routine signature.

**5. Post-mortem and reconciliation latency as its own signal (standing, reinforced this window)**

Three of this window's new items — WAX ("scope... remain to be further confirmed"), Railway (loss figure not independently confirmed), and CoinDCX (explanation and counter-evidence unreconciled) — all share the same shape: an alert goes out, and the actual scope stays unresolved for days. Reason from on-chain evidence and independent trackers (Blockaid, Bitquery, ZachXBT, Arkham, Monahan) rather than treating an initial alert or an official denial as the final word.
