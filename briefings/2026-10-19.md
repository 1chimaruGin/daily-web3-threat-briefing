## 1. 🔴 Active exploits / developing (last 24-48h)

### Qubic — Weak Wallet-Seed Generation Lets Attacker Drain 1,404 Wallets (~$1.3M), Mainnet Paused (Day 1)

**Chain:** Qubic (native mainnet).
**Status:** Active, first disclosed Oct 18, 2026. The drain ran from 23:42 UTC on Oct 17 to 01:26 UTC on Oct 18, during which an attacker swept approximately **2.94 trillion QU (~$1.3M)** out of 1,404 wallets. Qubic's developers halted the network (at tick 85,371,949) once the drain was detected. Of the stolen funds, **87.1% never left the Qubic network** and remains frozen on-chain in place; the remaining 12.9% reached MEXC, which froze the receiving account within about an hour. Bitget suspended QUBIC deposits/withdrawals as a precaution. Qubic shipped a patched wallet client (v4.26.4) addressing the seed-generation flaw; QEARN staking was unaffected. Compensation for victims is pending a vote by Qubic's "Computor" validator cluster, and affected users have been told to file police reports in the meantime.
**What happened / root cause:** Qubic's team says this was **not a bug in the network's protocol or consensus code**. It traces to weak, predictable wallet seeds generated on specific client surfaces: any browser on iPhone/iPad, Safari on Mac (until Oct 18, 2026), or the Qubic iOS app prior to July 2025. An attacker who identified the predictable seed-generation pattern could derive private keys directly for any wallet created under those conditions, without touching the chain's validation logic.
**Bug class:** key-management / weak-entropy-seed-generation (client-side wallet vulnerability affecting specific legacy app/browser/OS combinations, not a protocol-level exploit).

### Cysic — Compromised Bridge Database Lets Attacker Forge Mint Message, 10M CYS Minted, ~$727K Moved to Ethereum (Day 1)

**Chain:** BNB Smart Chain (mint/sale origin), Ethereum (destination of proceeds).
**Status:** Active, first disclosed Oct 17-19, 2026. At **12:31:38 UTC on Oct 17**, an attacker minted **10 million unauthorized CYS tokens** on BNB Smart Chain. Within five minutes the attacker began selling, ultimately offloading 7.2 million tokens (~72% of the mint) for roughly 588,315 USDT plus ~220 BNB, converting the proceeds to **~306.6 ETH (~$727,000)** and bridging them to Ethereum via Bridgers, Mayan, and deBridge, with transfers completed by 13:11 UTC. The Cysic Foundation blacklisted the address holding the remaining ~2.8 million unsold CYS at 13:47:52 UTC — about 76 minutes after the initial mint — restricting further transfers from that wallet. The bridge remains paused pending a security review, with no restoration timeline given; Cysic says mainnet, other operational systems, and existing user token holdings were not affected. The Foundation cautioned that "the number of tokens minted does not, by itself, represent the final loss" — the confirmed ~$727K figure reflects only the portion actually converted and moved off-chain so far.
**What happened / root cause:** Per Cysic Foundation's preliminary statement, the attacker gained **unauthorized access to a database supporting the bridge's off-chain infrastructure** and exploited a flaw in the bridge's message-processing logic to submit a fraudulent mint message, which the bridge accepted and executed without an independent on-chain check. The full attack path and root cause remain under investigation, with a professional security firm engaged and a follow-up report promised.
**Bug class:** access-control / off-chain-trust-compromise (bridge mint authorization relying on a backend database/message-processing service as a trust point, rather than solely on independently-verifiable on-chain proofs — a different mechanism from, but the same blast-radius lesson as, Autheo/Hyperlane's single-relayer-key compromise).

## 4. 🎯 What to hunt

**1. Client-side seed/entropy generation across every wallet-creation surface, not just the primary one (Qubic pattern, new this window)**

Qubic's bug sat dormant for over a year: wallets created via Safari on Mac, any iPhone/iPad browser, or an iOS app build predating July 2025 used predictable seed derivation, while the main web/desktop wallet path was presumably fine. For wallet-security work, don't just audit the flagship client — enumerate *every* platform/browser/legacy-version combination that can generate a seed, since weaker code paths can survive unnoticed for a long time precisely because they're less-used.

**2. Off-chain trust points in bridge mint-authorization pipelines (Cysic pattern, new this window — same lesson as Autheo, different mechanism)**

Two bridge incidents in the last week now show the same blast-radius pattern from different root causes: Autheo's Hyperlane route trusted a single relayer key to authorize minting; Cysic's bridge trusted a backend database/message-processing service, and a database compromise let an attacker forge a mint message outright. For any bridge audit: enumerate every component — key, relayer, database, API — whose compromise alone is sufficient to trigger a mint/release with no independent on-chain check, and ask what rate limit or multi-party requirement (if any) bounds the damage when that single point fails.

**3. Share/position accounting that double-counts across a release-then-cancel sequence (UNCX pattern, standing)**

Any vesting, staking, or shared-liquidity contract with separate release/cancel/withdraw paths touching a common share counter should be checked for whether every path that changes a position's share balance also updates every other counter derived from it — UNCX's `release()`/`cancel()` pair is the clean template.

**4. Freshly-deployed consensus/accounting upgrades remain a high-risk window (Pirate Chain Ironwood, standing)**

Any protocol that has shipped a consensus-level or supply-accounting change within the last 2-4 weeks deserves disproportionate scrutiny versus code that's been live for months.

**5. Operational/infrastructure compromise and social engineering, not contract bugs, continue to drive the largest losses (standing, reinforced this window)**

Qubic's root cause was client-side seed weakness, Cysic's was a backend database compromise, and the newest Ledger-adjacent losses are increasingly phishing, not the implant. None of this week's dollar-weighted damage came from a smart-contract logic bug. If you're doing wallet, exchange, or bridge-infra security work, treat client seed-generation code, backend/off-chain services in the authorization path, and social-engineering surfaces as at least as high-value a target list as the Solidity/Rust itself.

**6. Post-mortem latency as its own signal (standing)**

Cysic, Gamdom, Meter.io, DCENT, Fetch.ai, MultiversX, Blink, MALT, and GoldPesa all currently lack (or substantially lack) a primary technical post-mortem. Reason from on-chain evidence and third-party analysis (Blockaid, SlowMist, Bitquery, PeckShield, Arkham) rather than waiting for an official writeup that may never arrive in useful detail.
