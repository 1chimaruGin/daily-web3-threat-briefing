**Chain:** Bitcoin  
**Cumulative losses (waves 1–4):** ~1,816 BTC / ~$116M  
**Addresses drained:** 5,200+ (462 new suspected victims confirmed by Galaxy Research in Wave 4, detected August 3 UTC)  

**Wave summary:**

| 4 | Aug 3 | ~$27M / 462 addrs | P2WPKH | Funds moving |

**Attribution:** Still unattributed as of Aug 4. Investigators have not confirmed DPRK/Lazarus or any state actor link — Coinkite's statement attributed initial exploit discovery to AI-assisted open-source firmware analysis.

**Root cause (see Aug 1–3 briefings for full detail):** March 2021 Coldcard firmware build error silently routed seed generation to deterministic software PRNG (MicroPython Yasmarang) instead of STM32 hardware RNG. Mk3 effective entropy ~40 bits; Mk4/Mk5/Q pre-patch effective entropy ~72 bits — both brute-forceable at scale.

**Affected versions:**
- Mk3: firmware v4.0.0–v5.0.3 — **no patch available, permanently vulnerable; move funds NOW**
- Mk4 / Mk5: firmware before v5.6.0 — apply emergency update, then rotate seed
- Q: firmware before v1.5.0Q — apply emergency update, then rotate seed

**Critical reminder:** Updating firmware does NOT secure an already-compromised seed. Only moving to a fresh seed on patched (or different) hardware mitigates the risk.

**Bug class:** key-management

## 2. 🟡 New disclosed findings / techniques

### Adform CDN Supply-Chain Attack — JS Poisoning Swaps BTC/ETH/TRX Wallet Addresses Across 1,800 Sites

**Disclosed:** Early August 2026 (Adform detected and remediated July 27; public disclosure followed)  
**Scope:** ~1,800 downstream customer sites carrying Adform's advertising JS  
**Chains / assets targeted:** Bitcoin, Ethereum, Tron  

**What happened:**  
Attackers compromised Adform (a major ad-tech company) and modified `trackpoint-async.js`, a JavaScript file served from Adform's CDN to thousands of customer sites. The poisoned file acted as a browser-side clipboard hijacker and form-field manipulator, silently replacing any BTC, ETH, or TRX address the user copied or entered with an attacker-controlled address. Because the payload was delivered through Adform's trusted CDN infrastructure, no individual customer site was directly breached — they simply loaded malicious JS as if it were a legitimate analytics tag.

**Attack mechanics:**
1. Poisoned script monitors clipboard events (`copy`, `cut`, `paste`) and `input`/`change` events on form fields
2. String-matches any clipboard value or field input against regex patterns for Bitcoin P2PKH/P2WPKH/P2SH/bech32, Ethereum `0x...`, and Tron `T...` address formats
3. On match, silently replaces the address with an attacker-controlled wallet without user-visible indication
4. Because the injection happens client-side in the browser, server-side transaction logs show the legitimate user IP/session sending funds to a seemingly valid address

**Who is at risk:** Any user who visited a site embedding Adform JS during the July 27 window and performed a crypto transfer (deposit, withdrawal, send) during that time — specifically users who relied on copy-paste or browser autofill for wallet addresses.

**Defensive measures for developers and protocols:**
- Implement strict `Content-Security-Policy` headers (`script-src` allowlisting by hash or nonce, not domain) on any page with wallet-address input fields
- Add a client-side address checksum display and require explicit user confirmation step before submission
- Audit all third-party scripts loading on deposit/withdrawal/send pages — any third-party JS with clipboard access is a trust boundary
- Check if Adform scripts are embedded on your protocol's frontend and verify the current version hash against a known-clean baseline
- For end users: **always visually verify the full destination address character-by-character on a second device before confirming any crypto transaction**

**Adform response:** Detected the breach July 27, removed malicious code, notified affected clients, and reported to authorities. Recommended users clear browser caches as cached copies of the poisoned file may still execute.

**Bug class:** supply-chain

### Wanchain Cardano Bridge Signature Exploit — White-Hat Deadline T-2 Days

**Chain:** Cardano ↔ BNB Chain  
**Status:** No hacker contact as of Aug 4 UTC. Offer expires **August 6, 12:00 UTC** (~48 hours). Beyond that: law enforcement escalation and civil litigation.  
**At risk:** ~$10M / 515.2M NIGHT tokens  

**Recap of the root cause for hunters:** Wanchain's `TreasuryCheck` validator constructed signed messages by directly concatenating 14 variable-length fields (amount, token, chain ID, recipient, nonce, etc.) with no length markers or separators. This non-injective encoding allowed a single valid signature authorizing ~3,110 NIGHT on BNB Chain to be replayed as a Cardano withdrawal for 203,001,692 NIGHT — more than 65,000× the authorized amount.

**Hunt pattern:** Any bridge using `abi.encodePacked` (EVM) or raw byte concatenation (non-EVM) with multiple variable-length fields in signed authorization messages is potentially vulnerable to the same signature-reuse amplification. Grep target: `encodePacked` with combinations of `address`, `uint256`, `bytes`, and `string` parameters where total field count is ≥ 3 and amounts are in scope.

**Bug class:** signature-replay, bridge-dvn

**Affected library:** `web3` (Python/PyPI) — versions < 7.15.0 (stable) and < 8.0.0b2 (beta)  
**Severity:** HIGH  
**Vector:** `handle_offchain_lookup` and `async_handle_offchain_lookup` perform unsanitized HTTP requests to attacker-controlled gateway URLs embedded in smart contracts, enabling SSRF to AWS IMDSv1, GCP/Azure metadata endpoints, internal RPC nodes, and private APIs from any backend process calling these functions.  
**Fix:** `pip install "web3>=7.15.0"`  
Still unpatched across the majority of deployed Python-based oracles, relayers, and monitoring services three weeks after disclosure.

## 4. 🎯 Hunt hooks

**1. Audit third-party JS on your target's wallet-interaction pages — today.**  
The Adform attack is the year's second CDN-level supply chain hit on crypto frontends (Polymarket's $3M injection was June 28). The attack surface is the same each time: ad-tech, analytics, or tracking scripts that load with clipboard or DOM-write permissions on pages where users submit wallet addresses. Run these checks on any bug-bounty target:
- Load the deposit/withdrawal page in a browser dev tools session; capture all third-party script URLs in the Network tab
- Look for any script not explicitly permitted by a `Content-Security-Policy: script-src` header (or absence of CSP entirely — an automatic finding worth noting)
- Check whether address fields have any server-side or client-side verification before submission (checksum display, second confirmation)
- Specifically grep the source for Adform, Google Tag Manager, Meta Pixel, Hotjar, or any ad-tag integration loading on pages with wallet address input

**2. Coldcard key rotation still incomplete — protocol admin multisigs are the target.**  
Wave 4 demonstrates the attacker has automated enumeration of the entire vulnerable address space. The remaining risk is not just individual wallet holders — it's protocol admin keys, upgrade guardians, and pause-function signers generated on affected Coldcard devices. Ask in target protocol Discords or check deployment documentation for hardware wallet model used for admin key generation. A 4-of-7 Gnosis Safe with even two Mk3-derived signers has materially weakened security today.

**3. Grep target bridges for non-injective signed-message encoding.**  
Wanchain's 65,000× signature amplification came from joining variable-length fields without separators. In Solidity, the red flag is `abi.encodePacked` used with `address` (20 bytes, fixed), `uint256` (32 bytes, fixed) mixed with `string`, `bytes`, or multiple `uint` types where field-count manipulation is possible. In non-EVM bridges (Cosmos, Cardano), look for any authorization message schema where fields are concatenated without type-length-value (TLV) encoding or explicit delimiters. File it as HIGH if found in a bridge that moves user funds.
