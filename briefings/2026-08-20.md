## 1. 🔴 Active exploits (last 24h)

### MAYAChain — Six-Bug Chained Logic Exploit (Aug 19, 2026) — NEW

**Chain:** MAYAChain (Cosmos SDK / THORChain fork)
**Status:** NETWORK HALTED — Team confirmed halt on Aug 19; post-mortem published. No restart timeline.
**Stolen:** ~$1.65M in crypto assets ($1.36M moved to external chains; ~$291K remaining on-chain). Pool TVL fell ~$10.9M (mostly CACAO price collapse + arb, not direct theft).
**CACAO token:** -89% in 24h.

**How the attack worked (post-mortem reconstruction):**

The attacker sent a single 23-message `MsgDeposit` transaction that triggered a cascade across six compounding bugs in MAYAChain's slashing and liquidity accounting logic:

1. **False theft detection** — The chain's outbound monitoring incorrectly classified a pending transaction as "missing," triggering the slash-subsidy compensation path meant to make liquidity providers whole after a node theft.
2. **Uncapped slash subsidy** — The compensation formula contained no ceiling; the calculated payout was astronomically large relative to pool size, minting 49.45 million CACAO into the target pool.
3. **Pool share inflation** — With 99.93% of pool units suddenly held by the attacker's manipulated position, the pool's LP accounting treated the attacker as the near-sole liquidity provider.
4. **Immediate LP redemption** — The attacker immediately withdrew, collecting the inflated share of real underlying assets.
5. **Price oracle bypass** — The pool's internal spot price was only sampled at block boundaries; the multi-message single-tx structure kept the manipulation within one block, preventing price circuit-breakers from triggering.
6. **Fee/slip protection gap** — Slip-based fees designed to deter large single-side withdrawals were calculated against the post-inflation pool depth, not the pre-manipulation depth, rendering them ineffective.

**Bug class:** logic-error (uncapped slash subsidy + single-tx oracle bypass)

### Harmony ONE — Rollback Execution Day 3 (Aug 20): Database Swap In Progress

**Chain:** Harmony ONE
**Status:** CRITICAL / EXECUTION — Validator coordination continues; bridge.harmony.one remains suspended. No reactivation timeline.

The database-swap rollback targeting checkpoint blocks (Shard 0: 92,730,034 · Shard 1: 94,978,278) is in active execution. Validators must install the replacement database and upgrade to v2026.1.2 before chain can resume. As of Aug 20, a meaningful fraction of validators have not yet completed the swap, extending the network downtime window.

**Recap:** Aug 12 attacker exploited a cross-shard receipt bitmask flaw — quorum was declared by *counting* keys in a packed bitmask without verifying any actually signed the message. 3.01T ONE minted across six transactions; 97% reached exchanges before bridge halt.

**Active risk (new Day 3 angle):** Protocols with Harmony ONE deployments should confirm whether their contracts' `nonces` mappings, `processedMessages` maps, or multisig nonce counters were written *after* the rollback checkpoint. Any such state was erased — those messages are replayable post-restart.

**Bug class:** logic-error (signature bitmask counted keys without ecrecover verification), signature-replay

### Coldcard Bitcoin Entropy Exploit — Day 21 (Ongoing)

**Chain:** Bitcoin
**Status:** ONGOING — No confirmed new sweep wave in the Aug 19–20 window. Coinkite has not published a victim compensation framework. ~210K BTC self-migrated by users since disclosure.

| Coldcard Q series | < v1.5.0Q | Upgrade ≥ v1.5.0Q, fresh seed, migrate funds |

## 2. 🟡 New disclosed findings / techniques

### "Solidity Pro" Supply-Chain Poisoning — Targeted Attack on Web3 Developers (SlowMist, Aug 2026)

**Pattern:** A threat actor (attributed to North Korea–adjacent infrastructure by SlowMist) created a convincing fake IDE/extension called "Solidity Pro" distributed via GitHub and package registries. The actor forked OpenZeppelin Contracts, Foundry, Hardhat, Chainlink, Uniswap v3-core, and ethers.js under lookalike account names to serve as a credibility facade, then embedded a credential-harvesting payload that:
- Silently exfiltrates `.env` files, private key material, and shell history on first `npm install` / extension activation
- Hooks Hardhat's `compile` task to insert a phantom deploy step that calls an attacker-controlled relay with extracted keys
- Patches ethers.js `Wallet.signTransaction` locally to forward a copy of all signed transactions to the relay

**Why this matters for hunters:** Any developer who installed "Solidity Pro" or cloned from the lookalike repos may have already exposed all private keys visible to their dev machine — including deployer keys, audit environment keys, and hardware wallet signing keys used in test scripts. The relay received the exfiltrated data in real-time.

**Indicators to check:** Look for unexpected forks of canonical repos (OZ, Hardhat, Foundry, Chainlink) with "solidity-pro" or "solpro" in the account/org name. Check `npm list` for `@solidity-pro/*` or `solidity-pro` packages. Review `.npmrc` for registry redirects.

**Bug class:** supply-chain

**Source:** [SlowMist — Beware of Solidity Pro (Medium)](https://slowmist.medium.com/beware-of-solidity-pro-a-targeted-poisoning-attack-on-web3-developers-4c91a9892198)

### MAYAChain Slash-Subsidy Pattern — Uncapped Compensation Logic in DEX / AMM Forks

**Pattern:** The MAYAChain attack reveals a class of vulnerability in THORChain-derived codebases: **uncapped compensation paths** in slashing or insurance logic. When a node is penalized for losing funds, the protocol computes a payout to affected LPs — but if this calculation lacks a ceiling relative to pool depth, an attacker who can trigger the compensation path artificially (e.g., by simulating a missing outbound tx) can mint unbounded pool shares.

**Where to hunt this:**
- Any THORChain fork (MAYAChain, Vultisig, THORFI derivations) — inspect the `slashPool` / `compensatePool` / `yieldReserve` functions for uncapped arithmetic
- Cross-chain AMMs with internal settlement insurance funds — look for `insurancePayout()` or `compensate()` paths that write to pool balances without a `min(payout, poolDepth)` guard
- Cosmos SDK chains with custom module logic that touches LP accounting in penalty handlers

**Bug class:** logic-error

## 4. 🎯 Hunt hooks

**1. Slash/compensate paths in THORChain-derived codebases — hunt uncapped arithmetic TODAY**
The MAYAChain exploit is a blueprint. In any THORChain fork or cross-chain AMM that implements node-penalty compensation: find every function that writes to a pool's `balance`, `depth`, or LP unit count in a penalty / slash / insurance path. Ask: is there a `require(payout <= poolDepth)` or equivalent ceiling? Can the attacker control the inputs to the compensation formula (e.g., by manipulating what the chain perceives as a missing outbound tx)? The exact trigger — a `MsgDeposit` crafted to look like a theft — is now public. Forks that share the same accounting module are exploitable with the same primitive.

**2. Single-block oracle manipulation in multi-asset DEX forks**
The MAYAChain attacker kept all six messages within a single transaction (one block) to stay below price-circuit-breaker sampling intervals. Hunt for protocols where: (a) the pool price/depth snapshot is taken only at block boundaries, not per-message; and (b) a multi-message transaction can change pool composition significantly within that block. Look for missing per-message `_checkSlippage()` or `_priceImpactGuard()` calls in `MsgDeposit` / `MsgSwap` handlers.

**3. Dev-environment key hygiene audit — check for Solidity Pro indicators**
If you run bug-bounty tooling on a shared dev machine or CI environment: (a) `npm list | grep -i solidity-pro`; (b) check `~/.npmrc` and project `.npmrc` for redirected registry entries; (c) review recent `npm install` history for `@solidity-pro/*`; (d) check for unexpected modifications to `node_modules/ethers/lib/wallet.js` or equivalents. Any Hardhat project's `hardhat.config.js` should be inspected for injected `subtask` or `task` overrides. The "Solidity Pro" payload is designed to look like normal tooling.
