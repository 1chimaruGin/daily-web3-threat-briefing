### Coldcard Bitcoin Hack — Day 8: AI Attribution Confirmed, 15+ Attackers Still Active (~$130M Cumulative)

**Chain:** Bitcoin  
**Cumulative losses:** ~$130M (Galaxy Research, revised Aug 4 — no material revision since Aug 6)  
**Addresses swept total:** 5,900+ across all confirmed attack waves

**New August 6–7 developments:**

**AI-discovery attribution (new).** Coinkite issued a statement on August 5 acknowledging that, because Coldcard firmware is fully open-source, they must assume an attacker used frontier AI to systematically review older firmware commits and identify the 2021 PRNG regression. Ledger followed with a public blog post titled *"Coldcard Exploit Shows Bitcoin Wallet Security Must Adapt to AI"* (August 5), framing this as the first confirmed case of AI collapsing a 5-year-old embedded-firmware vulnerability window. PYMNTS and Forbes both picked up the AI angle August 6–7.

Key implication: the 2021 firmware commit that routed seed generation through MicroPython's Yasmarang software PRNG (instead of the STM32 hardware TRNG) was publicly reachable in git history for five years — a window that was too costly to exploit manually but now cost-effective for AI-assisted code review.

**Open-field competition (continuing).** 15+ independent attackers continue sweeping remaining vulnerable address space. The competitive dynamic means any Coldcard-generated seed in the weak-entropy range that has not been swept must be treated as actively at risk this hour.

**Law enforcement posture:** ~600 suspected attacker addresses flagged to federal investigators by Galaxy Research. No arrests or seizures announced as of August 7 UTC.

**Affected firmware (unchanged — move funds immediately if not done):**
- Mk3 (v4.0.0–v5.0.3): **no patch exists; move funds to a fresh seed on fixed hardware now**
- Mk4 / Mk5: firmware before v5.6.0 — update then rotate seed
- Q: firmware before v1.5.0Q — update then rotate seed

**Note:** Updating firmware alone is insufficient. The compromised seed must be rotated — move all funds to a new address generated on patched firmware before considering any wallet secure.

**Status as of Aug 7 UTC:** White-hat deadline expired August 6 at 12:00 UTC with zero hacker contact confirmed. Wanchain has initiated law enforcement escalation and civil litigation proceedings.

## 2. 🟡 New disclosed findings / techniques

### CHAINDROP — Second-Generation Shai-Hulud Worm: 1,280+ Packages, Bun Runtime, GitHub Exfil Repos (Aug 6–7)

**What's new vs yesterday's Shai-Hulud briefing:** Multiple security teams (Elastic Security Labs, Expel, StepSecurity, Microsoft MSRC, TechRadar, Infosecurity Magazine) published coordinated analyses on August 6–7 identifying **CHAINDROP** as a technically distinct, more capable variant — not just a scale-up of the original Shai-Hulud worm.

**Key technical differences from the original campaign:**

| | Shai-Hulud (Aug 4 initial) | CHAINDROP (Aug 5–6 confirmed) |
|---|---|---|
| Stage 2 runtime | Node.js (`Math_Symbol.js`) | Downloads **Bun** runtime (~62MB) then executes obfuscated payload |
| Propagation trigger | npm token with `bypass_2fa: true` | Same — but now also checks for **GitHub App** tokens with repo write scope |
| Exfiltration endpoint | Ethereum C2 contract + RSA-encrypted blob | Ethereum C2 contract + **public GitHub repos** named with Dune character names + description "Shai-Hulud: Here We Go Again" |
| IDE persistence | `.claude/settings.json` + `.vscode/tasks.json` | Same + **GitHub Copilot** workspace config injection |
| Package reach | 444 packages / 2,234 versions | **1,280+ packages / 1,381+ versions** (still growing) |
| Monthly install reach | ~2B | ~2B (confirmed figure from Elastic / TechRadar) |

**Web3-specific new impact:**
- The GitHub App token harvest means CHAINDROP is now stealing credentials that can open PRs and modify workflows on protocol repos — not just publish npm packages. A stolen GitHub App token on a DeFi protocol repo is a critical finding: it enables insertion of malicious code into the codebase itself with attributed commits.
- Bun runtime download is a **new CI/CD detection evasion**: Bun is not present in most devcontainer images, so its sudden download is a high-fidelity detection signal. Any CI pipeline that suddenly invokes `bun` via a temp path from an npm install hook should be flagged immediately.
- The public GitHub exfiltration repos are **open OSINT** — search GitHub for repos with description `Shai-Hulud: Here We Go Again` to identify which organizations have been compromised and whether your target protocol's org name or npm package names appear.

**Updated remediation (additions to yesterday's list):**
- Scan for unexpected Bun runtime binaries downloaded to temp paths during CI npm install steps
- Audit GitHub App tokens and OAuth apps granted to any npm-using maintainer account in your target protocol's org
- Search GitHub for public repos with description "Shai-Hulud: Here We Go Again" — any new repo in this set is a live exfiltration staging area
- Review all GitHub workflow runs since August 4 for unexpected `bun` invocations, new `.copilot/` workspace files, or unexplained branch creations

### AI-Assisted Open-Source Firmware Auditing as an Attack Vector (Coldcard Precedent)

**What it is:** The first publicly attributed case of an attacker (or nation-state actor) using frontier AI to audit open-source hardware wallet firmware and surface a 5-year-old entropy regression that was not caught by human reviewers or CI tests.

**The pattern:**
1. Target: open-source embedded firmware with public git history
2. Method: AI-assisted systematic commit-by-commit diff review, specifically targeting cryptographic primitive initialization
3. Detection window collapsed: a bug unreachable in 5 years of public audit became exploitable weeks after AI tooling made cost-effective at scale

**Where this generalizes:** Any protocol with open-source key derivation code, open-source node software with entropy initialization, or open-source hardware wallet integration should audit their public commit history for PRNG/entropy handling regressions back to 2021. Critical targets include: Ledger firmware (Ledger proactively clarified their entropy architecture was unaffected — but the AI-audit threat is now established), Foundation Passport, BitBox02, and any protocol-operated HSM wrapper code.

**Affected:** `web3` (Python/PyPI) < 7.15.0 stable / < 8.0.0b2 beta

## 4. 🎯 Hunt hooks

**1. Hunt CHAINDROP exfil repos for target protocol exposure.**  
CHAINDROP stages stolen credentials in public GitHub repos with description `Shai-Hulud: Here We Go Again`. Search GitHub for repositories with that exact description and check whether any of the exfiltrated credential blobs reference npm org names, GitHub org names, or repository names belonging to your target protocols. A confirmed credential leak from a protocol's CI environment — even without exploited funds yet — is a critical-severity report on most bug bounty programs covering deployment infrastructure. The repos are public and searchable *right now*.

**2. Grep target open-source key derivation code for PRNG initialization regressions from 2021–2023.**  
The Coldcard AI-discovery pattern is reproducible: run `git log --since="2021-01-01" --until="2023-12-31" --all -p -- "*rng*" "*entropy*" "*prng*" "*random*" "*seed*"` on any open-source wallet, node, or keygen library in your scope. Specifically look for commits that change which random source is called during key generation — a fallback from hardware TRNG to software PRNG is often a one-line diff that breaks 128-bit security down to 32–40-bit. If found in a live protocol with public funds, this is a critical finding regardless of whether it has been exploited.

**3. Hunt Wanchain-pattern `abi.encodePacked` signature amplification in bridge contracts — now.**  
The Wanchain post-mortem is coming within days and will saturate this hunt. Get ahead of it: search target bridge codebases for `abi.encodePacked` calls combining `address` (20B fixed) with any variable-length fields (`string`, `bytes`, dynamic arrays) where the packed result is passed to `keccak256` before being signed by a validator. Confirm exploitability by checking whether two different sets of field values can produce identical packed bytes — a sign that message encoding is non-injective. File as HIGH if the pattern is in a bridge authorization path. The Wanchain case achieved 65,000× amplification from a single valid signature.
